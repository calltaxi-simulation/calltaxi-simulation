# 데이터 출처

**대응 STRESS 항목: 3.1 데이터 출처**
(모든 데이터 출처를 나열하고 상술하라. **모든 출처 설명에 표본 크기, 표본 기간,
연구 내 용도를 포함하라.** 가능하면 링크·DOI·문헌 참조를 제공하라)

출처를 성격에 따라 두 표로 나눈다.

- **표 1 — 데이터 파일.** 행수·표본 기간이 정의되는 정형 자료. 행수·컬럼은 실제 파일을
  읽어 확인했고, 용도는 저장소를 grep 해 **어느 모듈·함수가 읽는지**로 적었다.
- **표 2 — 문헌·구술 근거.** 정보공개청구 답변, 기관 계획 문서, 조례, 인터뷰. 표본 크기
  개념이 맞지 않아 별도 표로 둔다.

용도 칸의 **"예정"** 은 자료는 확보했으나 `simulation/src/*` 어느 모듈도 아직 읽지 않는
경우다. 코드에서 확인되는 것과 어긋나는 진술은 **코드 쪽을 따랐고**, 어긋난 지점은
아래 [코드와 어긋난 지점](#코드와-어긋난-지점) 에 따로 적었다.

데이터 폴더는 `load.resolve_data_dir()` 이 정한다 — 환경변수 `DATA_DIR` 이 있으면 그쪽,
없으면 저장소 상위의 `../data/`. 아래는 모두 `C:\oracle\data` 기준이다.

## 코드와 어긋난 지점

작업 지시와 코드·파일 실물이 어긋난 곳이다. **모두 코드·파일 쪽을 따랐다.**

| 항목 | 지시 | 코드·파일 실물 | 이 문서의 처리 |
|---|---|---|---|
| 공영주차장 좌표 유효 건수 | 117 / 850 | `공영주차장_목록.csv` **2,189행 중 좌표 유효 1,456**(전부 시영), 무효 733(전부 구영). **117** 은 `시영주차장_목록.csv` 122행 중 공영 파일에 `PKLT_CD` 로 존재하는 행수다. **850** 에 해당하는 값은 어느 파일에서도 나오지 않는다 | 1,456 / 2,189 로 기록 |
| 공영·시영 주차장 목록의 코드 사용 | 아직 코드가 읽지 않음 | `공영주차장_목록.csv` 는 `load.load_candidates()` 가 **읽는다**(호출처는 `load.py.__main__` 진단 출력과 테스트). 다만 결과가 지표·시뮬로 흘러가지 않는다. `시영주차장_목록.csv` 는 정말로 아무 모듈도 읽지 않는다 | 두 파일 모두 "예정"으로 두되, 공영 파일은 읽는 함수가 있다는 점을 명시 |
| `동별_거점용량_접근성.csv` 생성 | `analysis/step4_distance.py` 산출물(`load_undersupplied` docstring) | step4 가 실제로 쓰는 파일은 `동별_거점거리.csv` 이고 컬럼이 다르다(`3km내차고지수` 는 있으나 `3km내차량대수`·`최근접차고지용량`·`공급수준` 은 없다) | 생성 코드가 저장소에 없다고 기록. `metrics.dong_supply()` 는 차고지 원본에서 직접 계산하므로 이 파일에 의존하지 않는다 |
