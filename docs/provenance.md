# 산출된 값 (provenance)

이 저장소의 스크립트를 그대로 돌려 얻은 **현재 값의 대장**이다. 어느 함수가 어떤 값을
내는지 확인하거나, 코드를 고친 뒤 값이 움직였는지 대조할 때 쓴다.

값의 **정의·필터·근거**는 [calibration.md](calibration.md) 에 있다. 이 문서는 정의를
다시 설명하지 않고 결과만 싣는다. 코드 밖 근거는 [external_sources.md](external_sources.md).

**자릿수 규칙 — 인용은 calibration, 대조는 여기.**

이 문서만 스크립트가 출력한 **원값을 그대로** 싣는다(`mean_wait 40.755280`). 코드를
고친 뒤 값이 움직였는지 보려면 반올림 전 자릿수가 필요해서다. **다른 문서가 인용하는
값은 [calibration.md](calibration.md) 의 반올림형**(`40.8분`)이고 README·assa_log 도
그쪽을 따른다 — 검증 기준의 정본이 calibration 이고, 허용오차(`TARGET_TOL`)가 대기시간
0.3~0.5분 단위라 그보다 잘게 적으면 없는 정밀도를 주장하게 된다.

**비율만 소수 둘째 자리까지 쓴다**(`15.44%` · `21.04%`). 허용오차가 0.2~0.5%p 라
첫째 자리로 접으면 판정 여유가 사라지고, 취소율처럼 0.04%p 차이가 정의 문제를
가르는 자리(정산 미기록 포함 여부)가 있어서다.

**여기 원값을 본문에 그대로 옮기지 말 것.** 대조용 자릿수이지 보고용이 아니다.

**재현 방법**

```bash
cd simulation
.venv\Scripts\python.exe src/load.py          # 데이터 로딩·필터·좌표매칭 요약
.venv\Scripts\python.exe src/travel_time.py   # 이동시간 테이블·커버율·오차
.venv\Scripts\python.exe src/metrics.py       # 동별 지표 산출 + 검증 대조
.venv\Scripts\python.exe src/idle.py          # 유휴 구간 건수·분포·시간대별 동시 유휴
.venv\Scripts\python.exe src/candidates.py    # 동별 후보 배정(규칙별 동 수·보류 목록)
.venv\Scripts\python.exe src/patience.py      # 인내심 KM 곡선
.venv\Scripts\python.exe src/evaluate.py      # 후보 244곳 평가
.venv\Scripts\python.exe src/sensitivity.py   # 가정 민감도
```

실행 환경은 `simulation/.venv` 다(전역 파이썬 아님). 검증된 버전 조합은
[README](../README.md#환경-설정) 참조.

데이터 폴더는 `load.resolve_data_dir()` 이 정한다 — 환경변수 `DATA_DIR` 이 있으면
그쪽, 없으면 저장소 상위의 `../data/`.

## 3. 대기 3구간 · 차내 (서울 합산, `metrics`)

| 구간 | n | 평균 | 중앙 | p90 |
|---|---|---|---|---|
| 총 대기 | 1,033,135 | 40.76분 | 31.96 | 80.38 |
| 매칭(배차−접수) | 1,033,135 | 21.98분 | 10.69 | 59.09 |
| 픽업(승차−배차) | 1,033,135 | 18.78분 | 17.81 | 29.40 |

**매칭 평균이 문서에 두 값으로 나온다 — 둘 다 맞고 분모가 다르다.** 위 표의
**21.98분**은 세 구간을 같은 모집단(승차 완료 1,033,135건)에서 재서 나란히 놓은
값이고, 1절의 **22.016분**(p90 59.279)은 **배차된 전 건 1,079,330건** 기준이다.
차이 46,195건은 배차는 됐으나 승차로 이어지지 않은 콜(배차 후 취소·미승차)이다.
구간 간 비교에는 표의 값을, 매칭 자체를 말할 때는 1절 값을 쓴다 — 인용할 때
어느 쪽인지 밝힐 것.

**매칭 대기가 픽업보다 더 많이 이동했다** — 매칭 20.82 → 21.98분(+1.16), 픽업
18.44 → 18.78분(+0.34). 대기 증가분의 3/4이 "차를 못 붙이는 시간"에서 나온다.
거리(픽업)보다 가용 차량 수(매칭)가 병목이라는 방향이고, 거점 재배치가 픽업을
줄이는 수단인 만큼 **개선 여지의 상한도 그만큼 좁다**는 뜻이다.

취소 건 중 배차 기록이 있는 건은 45,671건으로, `after_assign` 건수와 정확히 일치한다
(정산 미기록 524건은 취소가 아니라 여기서 빠진다).

차내(이상치 컷 통과 **1,026,086건**): 평균 25.70분 / 17.86km/h / 8.340km.
승차 완료 1,033,135건 중 7,049건이 컷에 걸리는데, 그중 **4,183건이 승차거리 0**
(calibration.md 흡수 사실 ⑴)이다.

동 중심점이 산 안에 있어 후보가 멀게 나오던 7동의 대표점을
**실측 승차거리로 역산**했다(`candidates.recalc_representative_points`).
방법·정확도·한계는 그 함수 docstring 에 있다. **7동 중 5동이 구제되고 2동이 남는다.**

| 성북구 정릉4동 | 1,456m | 1,557m | **692m** | ⑵ 1km대체 |

추정된 우회계수 중앙 **1.42**(전 동 중앙 1.33). `travel_time.DETOUR = 1.33` 과
독립적으로 얻은 값이고, 산지형 동은 우회가 더 크다는 방향도 상식과 맞는다.

**정릉1·3·4동이 같은 후보 한 곳(미아1동청사, 13면)을 가리킨다.** 세 동의 거점이
한 자리에 겹치고 그 자리는 13면뿐이라, **후보 품질로는 약한 구제**다. A-08(차고지별
10대 이상)과 맞물려 시뮬 뒤 후보를 좁힐 때 다시 봐야 한다.

**남은 2동은 후보 없음으로 확정한다.** 정릉2동(442m 이동)과 홍은2동(526m)은 이동량이
방법의 잡음 바닥(대표점 문제 없는 동에서 중앙 317m)과 크게 다르지 않다 — 즉
**중심점이 이미 그럭저럭 대표점이었고, 정말로 1.2km 안에 후보가 없다.**

**미배정 43개 동 — 후보 없음으로 확정.** 다만 수요가 없어서가 아니다.

| | 값 |

**이 동들이 빠지는 이유는 후보 풀이 옥외로 제한된 것(A-15)이지 진단에서 제외된 것이

## 12. 시뮬레이터

`src/simulator.py` 는 **뼈대만 있고 구현되지 않았다**(`raise NotImplementedError`).
따라서 **before/after 비교값·배치안 평가 결과는 아직 산출된 것이 없다.**

위 수치의 성격은 두 갈래다.

| 갈래 | 해당 | 성격 |
|---|---|---|
| **실측 집계값** | 1~9절 | 원본을 필터·집계해 센 값. 같은 원본이면 같은 값이 나온다 |
| **실측에서 추정한 값** | **10절 인내심 곡선** | 관측(포기 104,422 · 절단 107.9만)에 Kaplan-Meier 를 적용한 **추정치**다. 표본에 딸린 불확실성이 있고 꼬리는 특히 얇다(중앙 186분 지점의 위험집합 336건) |

**시뮬 산출값은 아직 없다.** 10절을 시뮬 결과로 읽지 말 것 — 그것은 시뮬의 **입력**이다.

`src/dashboard.py` 는 구현돼 있으나 **실측 지표를 보여줄 뿐 새 값을 만들지 않는다**
(입력은 `outputs/dong_metrics.csv` 등). 화면 결정은
[dashboard_spec.md](dashboard_spec.md) 참조.

정의된 상수만 있다: `SEED = 42`, `DISPATCH_RADIUS_DAY = 7km`,
`DISPATCH_RADIUS_NIGHT = 12km`(자동배차 탐색 반경 — 출처 확인 필요, 미확정).

## 13. 대표 기간 (A-03) — `src/simulator.slice_period`

시뮬은 연간 전체가 아니라 **대표 한 달**을 재생한다. 선정은 A-03 규칙대로
**연간 평균 대기에 가장 가까운 구간을 결과 확인 전에 고정**한 것이다.

| 항목 | 값 |
|---|---|
| **구간** | **2025-08-20 ~ 2025-09-18 (30일)** |
| 선정 근거 | 30일 창 365개 중 연간 평균 40.7553분과의 차가 최소 |
| 그 구간 평균 대기 | 40.7543분 (**차 0.001분**) |
| 콜 / 승차 | 108,223 / 91,344 |
| 차점 후보 | 02-24(차 0.022) · 05-11(0.028) · 08-19(0.102) |
| 30일 창 평균 대기 범위 | 34.41 ~ 46.56분 (주 단위 28.4~50.2 대비 폭이 좁다) |

**⚠ 시뮬은 연간 검증 기준이 아니라 아래 실측값과 대조한다.**

| 지표 | 대표 기간 | 연간 | 차이 |
|---|---|---|---|
| 평균 대기 | **40.75분** | 40.8 | −0.05 |
| 중앙값 | **32.01분** | 32.0 | +0.01 |
| p90 | **80.07분** | 80.4 | −0.33 |
| 60분 초과 | **18.54%** | 19.2% | −0.66 |
| 취소율 | **15.56%** | 15.44% | +0.12 |
| 지역 지니(총 대기 · 참고) | **0.1062** | 0.092 | **+0.014** |
| 대기 중 포기 | **9.26%** | 8.54% | +0.72 |
| **픽업 평균** (판정) | **18.797분** | 18.8 | −0.00 |
| **픽업 중앙** (판정) | **17.758분** | 17.8 | −0.04 |
| **픽업 p90** (판정) | **29.616분** | 29.4 | +0.22 |
| **픽업 지니** (판정) | **0.0751** | 0.0704 | +0.005 |

**지니만 크게 벌어지는데, 기간 효과이지 동 구성 효과가 아니다.** 한 달로 자르면
승차 100건을 넘는 동이 430 → **278개**로 줄지만, 그 278개 동만으로 연간을 다시
재면 0.0887 이다(전체 430개는 0.0924). 같은 동을 놓고 연간 0.0887 vs 대표월
0.1062 이므로 **차이는 짧은 기간이 만든 것**이다 — 동별 평균의 표본오차(동별 승차
중앙 138건)가 동 간 분산에 얹혀 지니를 위로 민다. 문턱을 25건으로 낮추면 422개
동이 남지만 지니는 0.1124 로 더 오른다(잡음이 늘어서다). **문턱은 100 을 유지하고,
대조 기준을 연간 0.092 가 아니라 대표월 0.1062 로 쓴다.**

재현: `python src/simulator.py` 가 쓰는 구간이며, 산출 스크립트는
`slice_period(calls, start="2025-08-20", days=30)`.
