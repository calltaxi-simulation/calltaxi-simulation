# 산출 근거 (provenance)

이 저장소가 내놓는 모든 수치가 **어떤 파일에서, 어떤 전처리를 거쳐, 어떤 정의로**
나오는지를 코드 기준으로 정리한 문서다. 값마다 산출 모듈·함수를 표기했다.

이 문서 하나로 전체를 파악할 수 있게 썼다 — `calibration.md` 와 겹치는 내용도
참조로 넘기지 않고 그대로 담았다.

**재현 방법**

```bash
cd simulation
.venv\Scripts\python.exe src/load.py          # 데이터 로딩·필터·좌표매칭 요약
.venv\Scripts\python.exe src/travel_time.py   # 이동시간 테이블·커버율·오차
.venv\Scripts\python.exe src/metrics.py       # 동별 지표 산출 + 검증 6개 대조
```

실행 환경은 `simulation/.venv` 다(전역 파이썬 아님). `requirements.txt` 가
**pandas 2.x 로 상한**을 두고 있고, 3.0 은 copy-on-write 기본화로 결과가 갈릴 수 있다.
검증된 조합: Python 3.14.3 / pandas 2.3.3 / numpy 2.5.1 / geopandas 1.1.4 / simpy 4.1.2 / pyarrow(parquet 캐시).

데이터 폴더는 `load.resolve_data_dir()` 이 정한다 — 환경변수 `DATA_DIR` 이 있으면 그쪽,
없으면 저장소 상위의 `../data/`. 아래 수치는 모두 `C:\oracle\data` 기준이다.

## 2. 전처리 기준

### 2.1 `load.load_calls()` — 콜 원본

500,000행 청크로 읽어 `_prepare_chunk()` 가 청크마다 아래를 적용한다.

| 단계 | 정의 | 상수 | 근거 |
|---|---|---|---|
| 즉시콜 | `\|예정일시 − 접수일시\| ≤ 2분` | `IMMEDIATE_TOLERANCE_MIN = 2` | 예약콜은 대기시간의 의미가 다르다. 시뮬 가정 S-02 는 예약콜을 재생하지 않고 가용차량에서 차감 |
| 서울 | `출발구 ∈ SEOUL_GU`(25구) | `SEOUL_GU` | 원본에 경기·인천 건이 섞여 있다. `require_seoul_dest=True` 면 목적지도 한정(기본 False) |
| 좌표 부착 | 출발·목적동에 중심좌표 merge | — | 3단계(아래) |
| 출발 좌표 필수 | `origin_lat.notna()` 인 행만 | — | 출발 좌표는 배차 계산에 필수. 실측에서는 한 건도 걸리지 않는다(아래) |
| 대기 이상치 | `wait_min < 0` 또는 `> 360` → **NaN**(행은 유지) | `MAX_WAIT_MIN = 360` | 행을 지우면 취소율 분모가 흔들린다. 실측 p99 가 127분이라 여유를 뒀다 |

**필터별 잔존 건수**

세 필터는 청크 안에서 연달아 적용돼 **코드는 단계별 중간 건수를 남기지 않는다**
(`attrs` 에는 `n_raw` 와 최종 건수만 있다). 아래는 같은 필터 체인을 따로 돌려 잰 값이다.

| 단계 | 잔존 | 제외 |
|---|---|---|
| 원본 | 1,729,476 | — |
| 즉시콜 `\|예정−접수\| ≤ 2분` | 1,527,474 | **202,002** (원본의 11.68%) |
| 서울 25구 출발 | 1,527,213 | **261** |
| 출발 좌표 확보 | **1,527,213** | **0** |

제외의 99.87%가 즉시콜 필터에서 나온다. 출발구가 서울 밖인 건은 261건뿐이고,
좌표 3단계 매칭은 서울 출발 건을 **하나도 놓치지 않는다**. 서울 중구로 잘못 적재된
인천 중구 동(영종동 등)은 전부 **목적지 쪽**에 있어 이 단계에서 걸리지 않는다.

**대기 이상치 컷은 실제로 아무 건도 제외하지 않았다.** 재계산 결과
`승차−접수 < 0` 0건, `> 360분` 0건이다. `wait_min` 의 NaN 203,593건은 전부
취소 건(= `boarded_at` 결측)이며 취소 건수와 정확히 일치한다.

**기간** 2025-01-01 ~ 2025-12-31 (`calls['date']` 최소·최대).

### 2.2 동 좌표 매칭 3단계 (`load.build_dong_lookup`, `load._attach_coords`)

콜 원본은 `고덕제1동`, 경계 파일은 `고덕1동` 표기라 그냥 두면 441개 조합 중 219개가
어긋난다. `analysis/step3_match.py` 와 같은 규칙이다.

- `load.canon_dong()` — 공백·가운뎃점(`·`)·마침표 제거 후, 숫자 앞의 `제` 를
  더 이상 바뀌지 않을 때까지 반복 제거(`성수2가제3동` 같은 중첩 대응)
- `load._base_dong()` — 표준형에서 숫자를 지우고 꼬리 `동` 을 뗀 기본명(`화곡1동` → `화곡`)

| 단계 | 방식 | 색인 키 | 조회표 키 수 | 매칭된 콜 건수 |
|---|---|---|---|---|
| exact | 표준형이 그대로 일치 | `key_kind='canon'` | 426 | 1,472,892 |
| manual | 행정구역 개편으로 개명(`MANUAL_DONG` 3건) | `key_kind='canon'` | 3 | 10,216 |
| approx | 분동/합동은 같은 기본명 그룹 중심점 **평균** | `key_kind='base'` | 245 | 44,105 |
| | | **계** | **674** | **1,527,213** |

`MANUAL_DONG` = {(종로구, 명륜3가동) → 혜화동, (동대문구, 용두동) → 용신동,
(동대문구, 신설동) → 용신동}. 용신동 = 용두동 + 신설동이다.

조회 순서는 **canon 먼저, 실패 시 base**. 어느 쪽에도 없으면 표에 넣지 않는다.

**목적동** 도 같은 절차를 거치지만 좌표가 없어도 행을 버리지 않는다.
`dest_match` 분포: exact 1,365,428 / approx 41,612 / manual 9,269 / **좌표없음 110,904(7.26%)**.
목적지가 서울인 건은 1,416,757건(92.77%)이다.

### 2.3 캐시 (`load._cache_path`, `travel_time._cache_paths`)

- 콜: `cache/calls_{o|od}_{mtime}_{size}.parquet`. 원본 mtime·크기를 파일명에 박아
  원본이 바뀌면 자동으로 빗나간다. 첫 실행 1~2분, 이후 재사용.
  `od` 태그는 `require_seoul_dest=True` 로 만든 캐시다.
- 이동시간: `cache/travel_{od|speed|profile}_{mtime}_{size}_{crc32}.parquet`.
  crc32 는 `(MIN_TRIPS, MIN_SPEED_TRIPS, PERIOD_CUTS, DIST_CUTS, RIDE_MIN_RANGE,
  SPEED_RANGE)` 의 해시라 **상수만 바꿔도 캐시가 무효화**된다.
- dtype 축소(`load._shrink`)는 청크를 합친 뒤 한 번에 한다 — 청크별로 하면 카테고리가
  어긋난다. 저카디널리티 문자열 12개 → `category`, 수치 10개 → `float32`.

### 2.4 `travel_time.load_rides()` — 이동시간용 필터 체인

원본은 `calltaxi_2025_merged.csv`. 단계별 잔존 건수는 `rides.attrs['funnel']` 에 담긴다.

| 단계 | 정의 | 잔존 | 제외 |
|---|---|---|---|
| 원본 | | 1,729,476 | — |
| 승차·하차 기록 | 두 시각이 **모두** 기록된 완료 운행 | 1,483,324 | 246,152 |
| 서울 내 | 출발구·목적구가 **모두** 서울 25구 | 1,368,451 | 114,873 |
| 시간·거리 정상 | 운행시간 1~120분 **and** 승차거리 > 0 | 1,361,426 | 7,025 |
| 속도 정상 | 평균속도 2~60km/h | **1,359,960** | 1,466 |

근거 — 취소·미탑승 건은 운행시간을 낼 수 없다. 경기·인천 편도는 동A→동B 서울 내
이동시간 표의 대상이 아니다. 나머지는 기록 오류(지연 하차 처리 등) 컷이다.

결과 중앙값 **19.6분 / 5.03km / 15.7km/h** (명세 참고 실측 20분 / 5.5km / 16km/h).

### 2.5 `load.load_vehicle_trips()` — 차량 생산성용 필터

같은 병합본을 읽지만 **목적이 달라 필터가 다르다.** 서울 밖 운행도 차량이 묶여 있던
시간이라 구를 가리지 않고, 대신 차량-일 집계의 키인 차량번호가 있어야 한다.

| 단계 | 정의 | 잔존 |
|---|---|---|
| 원본 | | 1,729,476 |
| 승차·하차 기록 + 운행 1~120분 | | 1,478,827 |
| 차량번호 있음 | `pd.to_numeric(차량번호).notna()` | **1,464,368** |

차량번호 결측 **14,459건**(완료 운행의 0.98%)이 빠진다 — `attrs['n_no_vehicle']` 에
남긴다. groupby 가 조용히 떨어뜨리게 두지 않으려는 것이다.

`service_date` 는 **승차 시각 기준**이라 자정을 넘긴 운행은 다음 날로 넘어간다.
심야 비중이 1.7%라 하루 단위 집계에 영향이 거의 없다.

### 2.6 `metrics` — 이상치 컷 · 동 키 · 신뢰 기준

**차내 지표 이상치 컷** (`metrics.ride_valid`) — `travel_time` 과 같은 상수를 import 해서 쓴다.

```
ride_min ∈ [1, 120]  and  ride_distance_m > 0  and  ride_kmh ∈ [2, 60]
```

승차 완료 1,323,620건 기준 걸린 건수(조건 간 중복 있음):

| 조건 | 건수 |
|---|---|
| 하차 미기록(승차 O, 하차 X) | 86 |
| 운행시간 1~120분 밖 | 3,488 |
| 승차거리 0 이하 | 5,681 |
| 속도 2~60km/h 밖 | 7,656 |
| **최종 유효 `n_ride`** | **1,314,350** (승차완료의 99.30%, 실제 제외 9,270) |

**동 키** = `(origin_gu, origin_dong_canon)` (`metrics.DONG_KEYS`). 콜 원본 기준
**432개**다. 경계 파일(426)·장애인 통계(427)와 행정구역 판이 서로 달라 어느 쪽도
완전히 겹치지 않는다. 조인 실패는 버리지 않고 NaN + 플래그로 남기고 건수를 `attrs` 에 적는다.

**신뢰 기준** (`MIN_CALLS_PER_DONG = 100`) — 콜수가 적은 동은 평균이 크게 흔들려
지니를 왜곡한다. 다만 **분모는 접수 건이 아니라 승차 완료 건(`n_served`)** 이다.
지니(`dong_wait_table`)와 모집단을 맞추려는 것이다. 접수 기준으로 재면 창신제3동
(접수 125 / 승차 95)이 표에서는 신뢰인데 지니에서는 빠져 두 지표가 어긋난다.

동별 표에서는 **버리지 않고 `is_reliable=False` 로 표시만 한다** — 지도에서
지워버리면 '데이터가 없는 동'과 구분이 안 된다. 지니 전용 집계
(`dong_wait_table`)에서는 아예 뺀다.

432개 중 신뢰 430개, 제외 2개:

| 구 | 동 | 승차 완료 | 평균대기 |
|---|---|---|---|
| 서초구 | 반포본동 | 24 | 49.97분 |
| 종로구 | 창신제3동 | 95 | 37.61분 |

## 3. 지표별 산출 방식

### 3.1 대기 3구간 (`metrics.dong_wait`)

| 구간 | 정의 | 분자 | 분모 |
|---|---|---|---|
| 매칭 `wait_match_*` | 배차 − 접수 (`assign_min`) | 배차 기록 있는 승차완료 건의 합 | `n_assigned` |
| 픽업 `wait_pickup_*` | 승차 − 배차 (`metrics.pickup_min`) | 〃 | 〃 |
| 총 `wait_total_*` | 승차 − 접수 (`wait_min`) | 승차완료 건의 합 | `n_served` |

각각 평균 / p50 / p90 세 컬럼을 낸다(`metrics._stats`). 집계 단위는 동.
**취소 건은 `wait_min` 이 NaN 이라 자동으로 빠진다** — 원본 분석의 동별 집계와 같은 정의다.

매칭·픽업은 원칙적으로 배차 기록이 있는 건만이라 총 대기보다 분모가 작을 수 있는데,
실측에서는 **승차 완료 건 1,323,620건이 전부 배차 기록을 갖고 있어 `n_assigned == n_served`** 다.
그래서 `매칭 평균 + 픽업 평균 = 총 평균` 이 정확히 성립한다(39.26 = 20.82 + 18.44).

### 3.2 장기대기 (`metrics.dong_wait` / `overall_metrics`)

`long_wait_ratio` = (`wait_min` > **60분**) 비율. 분모는 승차 완료 건.
상수 `LONG_WAIT_MIN = 60`. 원본 분석의 `장기대기율` 정의와 같다
(`동별_거점용량_접근성.csv` 는 퍼센트 표기라 `load_undersupplied` 가 100으로 나눠 맞춘다).

### 3.3 차내 (`metrics.dong_ride`)

| 컬럼 | 정의 |
|---|---|
| `ride_min_mean` | 하차 − 승차(분) 평균 |
| `ride_km_mean` | 승차거리 ÷ 1000 (원본이 미터) |
| `ride_kmh_mean` | `ride_km / (ride_min / 60)` — 콜별 속도를 낸 뒤 평균(구간 합계 비율 아님) |

분모는 `n_ride`(이상치 컷 통과분)이며 `n_served` 와 다르다.

### 3.4 취소 4구간 (`metrics.cancel_kind`, `dong_cancel`, `cancel_breakdown`)

취소를 한 덩어리로 두면 '변심'과 '기다리다 포기'가 섞여 공급 부족 신호가 묻힌다.
**배차 여부 × 취소까지 걸린 시간**으로 가른다. 승차한 건은 NaN.

| 구분 | 판정 |
|---|---|
| `immediate` 즉시 취소 | 배차 전 **and** 취소−접수 ≤ **1분** (`CANCEL_IMMEDIATE_MIN = 1.0`, 경계 포함) |
| `abandoned` 대기 중 포기 | 배차 전 **and** 1분 초과 — **공급 부족의 핵심 신호** |
| `after_assign` 배차 후 취소 | 배차 기록 있음 + 승차 기록 없음 |
| `other` 기타(불명) | 배차 전 취소인데 취소 시각이 결측이라 즉시/포기 판별 불가 |

`other` 를 `abandoned` 로 몰지 않는 이유는 근거 없는 분류가 공급 부족 신호를
오염시키기 때문이다(`tests/test_metrics.py::test_cancel_other_is_not_absorbed_into_abandoned`).
취소 시각이 접수보다 앞선 기록이 소수 있는데 `immediate` 로 들어간다(오차 무시).

**같은 분해를 분모 둘로 낸다.** 답하는 질문이 다르다.

| 관점 | 컬럼 | 분모 | 질문 |
|---|---|---|---|
| 콜 대비 | `cancel_{종류}_ratio` | 그 동의 **전체 접수 콜**(취소 포함) | 이 동에서 콜을 넣으면 얼마나 미이행되나 |
| 취소 내 구성비 | `cancel_{종류}_share` | 그 동의 **전체 취소 건** | 미이행된 콜이 왜 미이행됐나 |

`ratio` 4개의 합 = `cancel_ratio`, `share` 4개의 합 = 1 로 정확히 맞는다(테스트로 고정).
**검증 채점과 전체 취소율 13.3%는 `ratio`(콜 대비) 기준**이고 `share` 는 해석용이다.
취소가 한 건도 없는 동은 `share` 가 NaN 이다 — 0으로 채우면 '전부 즉시 취소였다'와
구분이 안 된다.

`cancel_breakdown()` 은 동별 표를 평균 낸 게 아니라 **건수를 그대로 합친 서울 합산**이다.
동 균등가중 평균과 값이 다르다(4.5 참조).

### 3.5 콜 발생 (`metrics.dong_demand`, `demand_matrix`)

- `n_calls` = 접수 콜 수(취소 포함). 집계 단위 동.
- 시간대 4구간 분해 `n_calls_{night,morning,day,evening}` — `load.time_period()` 가
  `PERIOD_BINS = [0, 6, 10, 17, 22, 24]`, 라벨 `[심야, 아침, 낮, 저녁, 심야]`,
  `right=False` 로 자른 것이다. 즉 **심야 0~5시 + 22~23시 / 아침 6~9 / 낮 10~16 / 저녁 17~21**.
- 평일/주말 분해 — `weekday >= 5`(토·일).
- 좌표는 `load_calls` 가 행마다 붙여둔 출발동 중심점(동 안에서 같은 값)을 `first` 로 집는다.
- `demand_matrix()` 는 같은 재료를 접지 않은 long form (동 × 시간대 × 평일/주말)으로 남긴다.

⚠ **이 4구간은 `travel_time` 의 5구간과 기준이 다르다.** 섞어 쓰면 안 된다(3.9 참조).

### 3.6 이용률 (`metrics.dong_population`, `build_dong_table`)

`usage_rate` = **연간 접수 콜 ÷ 동별 등록 장애인**. 1인당 몇 번 불렀나.

통계 원본(`서울시_장애인_통계_2025.csv`)은 정형이 아니라 `load_disabled_population()`
이 세 가지를 흡수한다.

- 행 끝 쉼표로 열 수가 어긋난 행 → `on_bad_lines='skip'` + `engine='python'`
- 구 컬럼이 없고 `동별` 한 컬럼에 총계·구·동·`기타` 가 섞임 → 구 행이 앞에 오는 순서에
  기대어 `ffill` 로 구를 채움
- 값이 `-` 인 칸 → NaN
- `장애유형별 == 합계` **and** `성별 == 계` 행만, 연도 컬럼은 정규식으로 찾은 **마지막 연도**

`합계`·구 행·`기타`(동 단위가 없는 잔여분)를 빼면 **427개 동, 384,921명**. 표 전체
합계 384,934명과 13명 차이다.

두 파일의 행정구역 판이 달라 표준형만으로는 432개 중 18개가 안 맞는다.
**어긋나는 방향에 따라 둘로 나눠 처리한다. 둘 다 나누는 게 아니라 합치는 것이라 근거가 있다.**

| 방향 | 처리 | 결과 컬럼 |
|---|---|---|
| 콜이 더 뭉뚱그림 (강동구 상일동 ↔ 통계 상일1·2동) | 통계 쪽을 기본명 그룹으로 합산해 그 동에 붙인다 | `pop_match='base'` |
| 콜이 더 잘게 쪼갬 (중구 신당1~6동 ↔ 통계 신당동) | **콜도** 같은 기본명 그룹으로 합산해 분자·분모의 단위를 맞춘다 | `usage_is_grouped=True` |

세부 규칙:
- 기본명 그룹을 **두 개 이상의 동이 다투면 `n_disabled` 를 붙이지 않는다** — 통계 한 줄을
  어떻게 나눌지 근거가 없어서다.
- 이미 표준형으로 붙은 통계 행은 기본명 후보에서 뺀다(공릉2동 이중 계상 방지).
- `min_count=1` — 통계값이 `-`(NaN)뿐인 그룹까지 0명으로 만들면 안 된다(반포본동).
- `pop_group` 은 잔여분이 아니라 **그룹 전체** 인구다. 답십리3·4동을 살리려면 이미 정확히
  붙은 답십리1·2동의 인구까지 분모에 들어가야 하고, 그러려면 콜도 4개 동을 다 더해야 한다.

**`n_disabled` 와 `usage_pop` 은 다른 값이다.** `n_disabled` 는 그 동 하나에 귀속되는
인구라 서울 전체 합(378,097)이 통계 총합(384,921)을 넘지 않는다. `usage_pop` 은
이용률의 실제 분모이고 그룹 안에서 중복되므로 **합계를 내면 안 된다.**

### 3.7 3km 근접도 (`metrics.dong_supply`)

`vehicles_3km` = 동 중심점 반경 `SUPPLY_RADIUS_KM = 3.0` km 안 차고지의 **배속 차량 합**
(차고지 수가 아니라 `capacity` 합). `n_depots_3km` 는 차고지 개수.

거리는 `travel_time.haversine_km()`(지구 반경 6371.0088km) 직선거리다.
432 × 44 행렬을 전수 계산한 뒤 불리언 마스크와 `capacity` 벡터를 내적한다.

### 3.8 지니 (`metrics.dong_gini`, `gini`)

동간 대기시간 지니. **동 균등가중이 정본이다.**

- 집계 단위: `dong_wait_table()` 이 내는 (구, **원본 표기 동명**) 별 평균대기.
  동명을 표준형으로 바꾸지 않는 이유는 원본 산출물과 직접 대조하기 위해서다.
- 분모: 승차 완료 건 100건 이상 동 **430개**. 미달 동은 아예 뺀다.
- 정렬 후 누적합 공식: `G = 1 − Σ wᵢ(Sᵢ₋₁ + Sᵢ) / (W · Sₙ)`, `S = 누적 Σ w·x`, `W = Σ w`.
  쌍별 이중루프는 430개에도 느리다.
- NaN·비양수 가중치 행은 버리고, 음수 값에는 `ValueError` 를 낸다(대기시간은 0 이상).
- 형평을 '동 간 격차'로 정의하므로 각 동을 한 표로 센다. 콜수로 가중하면 콜이 많은
  동이 지표를 지배해 정작 소외된 동의 격차가 묻힌다. `weighted=True` 로 콜수 가중도
  뽑을 수 있지만 **참고용이며 검증 채점에는 쓰지 않는다.**

### 3.9 이동시간 (`travel_time`)

`get_travel_time(출발동, 목적동, hour, is_weekend) -> float` — 조회는 딕셔너리 1회.
3단 폴백으로 임의의 동쌍을 빠짐없이 커버한다.

| 순위 | 키 | 값 | 조건 |
|---|---|---|---|
| 1 `od` | (출발동, 목적동, 시간대, 주말) | 실측 운행시간 **중앙값** | 셀 건수 ≥ `MIN_TRIPS = 10` |
| 2 `speed` | (거리대, 시간대, 주말) | 직선거리 × `DETOUR` ÷ 중앙속도 | 셀 건수 ≥ `MIN_SPEED_TRIPS = 30` |
| 3 `line` | (시간대, 주말) | 직선거리 × `DETOUR` ÷ 시간대 중앙속도 | 위 셀이 비었을 때 |
| `intra` | 출발동 == 목적동 | 실측 동일-동 중앙값 | 표본 < 10건이면 `MIN_INTRA_MINUTES = 5.0` |
| `default` | 좌표 없음 | 시간대 운행시간 중앙값 | 중심점을 못 찾는 동 |

- **시간대 5구간** `PERIOD_CUTS = (7, 10, 16, 19)` → 심야 0~6 / 오전피크 7~9 / 낮 10~15 /
  오후피크 16~18 / 저녁 19~23. 혼잡 반영이 목적이라 `load.py` 의 대기 집계용 4구간과 다르다.
- **거리대 5구간** `DIST_CUTS = (2.0, 5.0, 10.0, 20.0)` → `~2km` / `2-5km` / `5-10km` /
  `10-20km` / `20km+`. 거리대는 실측 `승차거리`(도로거리) 기준으로 나누고, 조회할 때도
  직선거리 × `DETOUR` 로 도로거리를 추정해 기준을 맞춘다.
- **반환값 가드** `MIN_MINUTES=1.0`, `MAX_MINUTES=120.0` 로 클립. 프로필까지 비면
  `FALLBACK_KMH=16.0` / `FALLBACK_MINUTES=20.0`.
- **동명만으로 조회한다** — 시그니처가 구를 받지 않아 `신사동`(강남·관악)처럼 겹치는
  동명은 중심점을 평균한다(`attrs['n_ambiguous']`).
- `lookup_many()` 는 같은 폴백 사슬을 merge 로 옮긴 벡터판이라 스칼라 `lookup()` 과
  결과가 동일하다.

`load_centroids()` 의 키는 `load.build_dong_lookup()` 과 규칙은 같되 **구를 쓰지 않는다**:
canon → alias(`MANUAL_DONG` 개명 동) → base 순으로 concat 하고 동명 중복은
`keep='first'` 로 canon 을 우선한다.

### 3.10 차량 생산성 (`metrics.vehicle_day_table`, `vehicle_productivity`)

동별 아님 — **차량-일 단위** 집계다.

| 지표 | 정의 |
|---|---|
| `trips_per_day` | 차량-일별 운행 건수의 평균 (모든 차량-일 포함) |
| `trips_per_hour` | `trips / span_h` 를 차량-일마다 낸 뒤 평균 |
| `occupied_ratio` | 실차율 = `occupied_min/60 ÷ span_h` 를 차량-일마다 낸 뒤 평균 |

- `span_h`(가동시간) = 그날 **첫 승차 ~ 마지막 하차**. 배차를 기다리며 서 있던 시간은
  운행 기록에 안 남아 이 방법 말고는 알 길이 없다.
- `occupied_min` = 그날 `ride_min` 의 합(승차~하차).
- 운행이 1건뿐인 날은 `span` 이 0에 가까워 시간당 통행이 발산한다 →
  `min_span_h = 0.5` 미만 차량-일은 **비율 계산에서만** 뺀다(`trips_per_day` 는 전부 포함).
  제외 건수는 `n_vehicle_days_dropped` 로 남긴다.

### 3.11 구/서울 평균 대비 (`metrics.add_comparisons`)

각 동 값에 `{col}_gu_mean`, `{col}_seoul_mean`, `{col}_vs_gu`, `{col}_vs_seoul` 을 붙인다.
`vs_*` 는 배수다(1.2 면 기준선보다 20% 높다).

기준선은 **동 균등가중 평균**이다(콜수 가중 아님) — 형평을 동 간 격차로 보는 지니와
관점을 맞춘 것이다. 표본이 얇은 동이 기준선을 흔들지 않도록 **기준선은 신뢰 동(430개)
만으로** 내되, 비율 자체는 모든 동에 계산한다.

대상 컬럼(`COMPARE_COLS`): `wait_total_mean`, `long_wait_ratio`,
`cancel_abandoned_ratio`, `usage_rate`, `vehicles_3km`.

## 5. 알려진 한계

### 5.1 대기 지표

- **취소 건은 대기 통계에 없다.** 승차 완료 건만 분모라, 오래 기다리다 포기한 콜의
  '실제로 겪은 대기'는 평균 39.3분에 반영되지 않는다. 공급이 나쁠수록 포기가 늘어
  **대기 평균이 오히려 좋아 보이는 방향으로 치우친다.** 이 누락분은 취소 4구간의
  `abandoned`(6.84%)가 따로 답한다.
- **매칭/픽업 분해는 배차 기록에 의존한다.** 배차 시각이 실제 차량 배정 시점인지
  시스템 기록 시점인지는 원본만으로 알 수 없다.
- **동 단위는 출발동 기준**이다. 목적지 쪽 대기 특성은 이 표로 답할 수 없다.

### 5.2 취소 4구간

- **`other` 24건은 판별 불가**다. 취소 시각이 결측이라 즉시/포기를 가를 수 없어
  별도 구간으로 뒀다. 근거 없이 `abandoned` 로 몰면 공급 부족 신호가 오염된다.
- **1분 컷은 규칙이지 관측이 아니다.** 접수 30초 뒤 취소를 '변심'으로 보는 것은
  가정이며, 실제 사유는 원본에 없다.
- **`after_assign` 60,549건의 원인을 구분할 수 없다.** 차가 오다 어긋난 건지,
  이용자가 취소한 건지, 기사 사정인지 기록이 없다.
- **서울 합산과 동 균등가중 평균이 다르다**(13.3% vs 15.0%). 콜이 많은 동이
  합산에서 더 무겁다. 인용 시 기준 명시가 필요하다.

### 5.3 이동시간

- **1순위 커버가 79.9%인 이유** — OD쌍만으로 끊으면 90.0%지만 시간대·요일까지
  나누면 셀이 얇아져 20%가 2순위로 내려간다(요일만 86.7%, 시간대만 83.2%).
  피크 혼잡 반영과 맞바꾼 것이고, 2순위 절대중앙오차가 5.0분이라 감수할 만하다.
- **2순위는 거리대 안에서 속도를 하나로 뭉갠다.** 거리대 양끝이 치우치고,
  `~2km` 는 +0.8분 과대, `20km+` 는 −1.2분 과소로 남는다.
- **좌표없음 폴백 323건은 오차 57.3분**이다. 전부 **목적동** 쪽이 중심점 표에 없는
  건으로, 서울 중구로 잘못 적재된 인천 중구 동이다 — 영종동 266 / 율목동 19 /
  북성동 18 / 신흥동 14 / 도원동 4 / 연안동 2. 실제로는 서울 밖 장거리인데 서울
  중앙값 20분으로 답한다. 전체의 0.02%라 지표에는 영향이 없다.
- **동명만으로 조회한다.** 구를 받지 않는 시그니처라 `신사동`(강남·관악)은 중심점을
  평균하고 실측도 한 셀에 섞인다. 425개 중 1개다.
- **커버율·오차는 전부 in-sample** 이다 — 표를 만든 데이터로 표를 평가한 값이라
  실제 예측 오차는 이보다 클 수 있다.
- **중심점 간 직선거리 × 1.36 이다.** 동 안 어디서 타고 내렸는지는 알 수 없어,
  같은 동쌍이면 항상 같은 거리로 취급한다.
- **시간대 구분이 `load.py` 와 다르다.** `load` 는 대기 집계용 4구간, `travel_time` 은
  혼잡 반영용 5구간이다. 섞어 쓰면 안 된다.

### 5.4 이용률

- **NaN 2개 동** — 명륜3가동은 통계 쪽 대응 행이 아예 없고(개편으로 혜화동에 흡수),
  반포본동은 통계값이 `-`(집계 없음)다. 0으로 채우면 이용률이 무한대로 튄다.
- **그룹 합산한 24개 동은 동 간 격차를 못 본다.** 신당1~6동이 모두 같은 이용률을
  갖는다는 뜻이라, 그룹 안에서 어느 동이 더 많이 쓰는지는 이 지표로 답할 수 없다.
  통계가 그 단위로만 나와 있어서고, 동별 분해가 필요하면 원천 통계를 동 단위로
  다시 받아야 한다.
- **분자는 출발동, 분모는 등록지다.** 신촌동 76.4회/명, 이화동 64.6회/명처럼 상위
  값은 '그 동 주민이 많이 쓴다'가 아니라 **병원·대학·상권이 있어 외부 이용자가 그 동에서
  콜을 부른다**는 뜻에 가깝다. 이용률은 인구 대비 수요 강도의 근사일 뿐 개인 이용 빈도가 아니다.
- **통계 기준 시점이 콜 기간과 다르다.** 콜은 2025년 1년치, 통계 파일은 2026-05
  기준(값 컬럼은 `2025 년`)이다.
- **`n_disabled` 합 378,097 ≠ 통계 총합 384,921.** 다투는 기본명 그룹에는 귀속 인구를
  붙이지 않아 6,824명이 어느 동에도 귀속되지 않는다. `usage_pop` 은 그룹 안에서
  중복되므로 합계를 내면 안 된다.

### 5.5 3km 근접도

- **직선거리라 낙관적이다.** 실제 접근은 도로를 타므로 3km 안이어도 더 걸린다.
- **계단 함수다.** 반경에 걸친 차고지는 들어오거나 빠지거나로 갈려, 3.01km 차고지는
  0으로 센다.
- **정원이지 실제 배치가 아니다.** `capacity` 는 차고지 수용대수라, 그 시각에 그
  차량이 거기 있었는지는 반영하지 않는다.
- **동 중심점 하나로 동 전체를 대표한다.** 면적이 넓은 동(내곡동 등)은 실제 편차가 크다.

### 5.6 지니

- **동 균등가중이라 인구·콜수를 반영하지 않는다.** 콜 24건 동과 33,000건 동이 같은
  한 표다. 이게 정의(형평 = 동 간 격차)이지만, '사람 기준 불평등'과는 다른 값이다.
  콜수 가중은 0.1013 으로 더 크다.
- **100건 미만 동 2개가 빠진다.** 표본이 얇은 동이 오히려 소외 동일 수 있는데
  모집단에서 제외된다.
- **평균대기만 본다.** 같은 평균이라도 분산이 다른 동을 구분하지 못한다.
- **취소는 안 들어간다.** 대기 격차가 작아도 취소 격차가 클 수 있다.

### 5.7 콜 발생 · 수요

- **즉시콜만이다.** `|예정−접수| > 2분` 인 202,002건(원본의 11.68%)이 빠져 있어
  총 수요가 아니다. 시뮬 가정 S-02 는 예약콜을 재생하지 않고 가용차량에서 차감한다.
- **접수된 콜만 센다.** 대기가 길어 아예 부르지 않게 된 잠재 수요(억제된 수요)는
  어떤 지표로도 보이지 않는다.
- **1년치 합계라 계절성·추세를 접었다.** `demand_matrix` 도 시간대 × 평일/주말까지만
  쪼갠다. 월·주 단위 변동을 보려면 원본에서 다시 집계해야 한다.

### 5.8 차내 지표

- **속도는 콜별 속도의 평균**이다(총거리 ÷ 총시간이 아님). 짧은 운행이 상대적으로
  더 무겁게 반영된다.
- **승차거리는 미터로 기록된 값을 그대로 믿는다.** 미터기 기준인지 경로 기준인지
  원본에 정의가 없다.
- **이상치 컷 9,270건(0.7%)의 성격을 가리지 않았다.** 기록 오류와 실제 특이 운행
  (장시간 대기 후 하차 처리 등)이 같이 빠진다.

### 5.9 차량 생산성

- **실차율 46.4%는 상한이다.** 가동시간을 그날 첫 승차~마지막 하차(span)로 잡아서
  출근 후 첫 콜까지, 마지막 하차 뒤 퇴근까지의 유휴가 분모에서 빠진다. 반대로 기사
  휴게는 분모에 그대로 들어가 값을 낮추는 쪽으로 작용하는데, 둘을 가를 근거가 원본에
  없다. 정확한 가동시간은 **배차 로그**가 있어야 나온다.
- **877대는 특정 시점 가동 대수가 아니다.** 1년 누계라 중간에 교체·증차된 차량이
  모두 잡힌다. 차고지 정원 합 691대와 직접 비교하면 안 된다.
- **차량번호 없는 14,459건(0.98%)이 빠진다.** 승차·하차가 다 있는 완료 운행인데
  원본 병합이 차량을 못 붙인 건이라 차량-일 집계의 키가 없다.
- **`service_date` 는 승차 시각 기준**이라 자정을 넘긴 운행은 다음 날로 잡힌다.
  심야 비중 1.7%라 영향은 작지만 0은 아니다.
- **공차 이동·대기 위치가 기록에 없다.** 차량이 어디서 대기했는지 알 수 없어
  거점 배치 효과를 실측으로 검증할 수 없다 — 시뮬이 필요한 이유다.

### 5.10 데이터·재현성

- **후보지 풀이 시영 전용이다.** `공영주차장_목록.csv` 2,189곳 중 좌표가 있는 건
  시영 1,456곳뿐이고, 자치구영 733곳은 `LAT`/`LOT` 가 전부 0 이다. 구영을 후보에
  넣으려면 `analysis/step1_geocode.py` 로 주소 지오코딩을 먼저 돌려야 한다.
- **목적동 좌표 결측 7.3%.** 대부분 서울 밖 목적지다. 서울 내 미매칭은 극소수이며
  전부 인천 중구 동이 서울 중구로 잘못 적재된 건이다.
- **`동별_거점용량_접근성.csv` 를 만드는 코드가 저장소에 없다.** `load.load_undersupplied()`
  의 docstring 은 `analysis/step4_distance.py` 산출물이라고 적고 있으나, step4 가
  실제로 쓰는 파일은 `동별_거점거리.csv` 이고 컬럼이 다르다(`3km내차고지수` 는 있으나
  `3km내차량대수`·`최근접차고지용량`·`공급수준` 은 없다). 과소공급 68개 동은 이 CSV 를
  그대로 신뢰한 값이다. `metrics.dong_supply()` 는 차고지 원본에서 직접 계산하므로
  이 파일에 의존하지 않는다.
- **원본 집계 스크립트가 없다.** 즉시콜·서울 필터 후 132만을 만든 스크립트는 저장소에
  없고 산출물 CSV(`서울즉시콜_*.csv`)만 있다. `load.py` 가 그 역할을 대체하며 취소
  콜까지 보존해 152.7만으로 확장했다. 동별 건수는 원본과 완전히 일치하고(공통 430개
  동 차이 0), 동별 평균대기도 최대 0.05분 차이(원본 반올림)다 —
  `tests/test_metrics.py::test_dong_means_match_original_analysis` 가 고정한다.
- **행정구역 판이 세 갈래다.** 콜 432개 동 / 경계 426개 / 통계 427개. 어느 쪽도
  완전히 겹치지 않아 조인마다 별도 규칙이 필요하다.
- **`load_disabled_population()` 은 원본 행 순서에 의존한다.** 구 행이 그 구의 동들
  앞에 오는 순서에 기대어 `ffill` 로 구를 채우므로, 원본 정렬이 바뀌면 깨진다.
- **좌표계** — GeoJSON 원본은 EPSG:4326 이다. 미터 단위 거리가 필요하면
  `load_dong(with_boundary=True, crs=5179)` 로 투영좌표를 받는다. 현재 지표 계산은
  전부 haversine 직선거리라 투영을 쓰지 않는다.
