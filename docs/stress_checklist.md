# STRESS-DES 체크리스트

STRESS(Strengthening The Reporting of Empirical Simulation Studies) v1.1 중
이산사건 시뮬레이션(DES) 보고 표준의 원문 요구사항이다. 각 항목은 시뮬레이션
연구를 다른 사람이 이해·재현할 수 있도록 보고서에 무엇을 담아야 하는지를 규정한다.

문서 실물이 없으면 결정이 있어도 미충족으로 둔다. 요구사항을 충족하면 ☐를 지운다.

---

## 1. 목적 (Objectives)

### ☐ 1.1 모델의 목적

모델의 배경과 목적을 설명하라.

### ☐ 1.2 모델 산출물

보고되는 모든 정량적 성과지표를 정의하라(필요 시 수식 사용). 각 지표를 실행 중
언제·어떻게 계산하는지, 신뢰구간 등 오차 측정치는 어떻게 계산하는지 명시하라.

### ☐ 1.3 실험 목표

모델로 실험을 수행했다면 조사 목표를 기술하라.

- **시나리오 분석** — 각 시나리오의 이름·설명과 선정 근거를 제시하고 2.3을 완성할 것.
- **실험계획법** — 성과지표·파라미터와 연결된 전체 실험 설계를 기술할 것.
- **시뮬레이션 최적화(해당 시)** — 최적화 대상, 포함한 파라미터, 사용 알고리즘을
  상세히 기술하고 가능하면 알고리즘을 인용할 것.

## 2. 로직 (Logic)

### 2.1 기본 모델 개요 다이어그램

적절한 다이어그램과 설명으로 기본 모델을 기술하라. 프로세스 흐름도, 활동주기도
또는 그에 상응하는 다이어그램을 하나 이상 포함하라. 본문에는 복잡한 다이어그램을
피하라. 목표는 연구 대상 시스템에 대해 모델의 폭과 깊이를 전달하는 것이다.

→ [docs/model_flow.md](model_flow.md) — mermaid 프로세스 흐름도(이탈 경로 포함), 조 편성, 단계별 모듈·함수 대응, 모델 경계

### ☐ 2.2 기본 모델 로직

기본 모델의 로직을 상세히 제시하라. 독자가 모델의 작동 방식을 이해하기에 충분한
설명을 제공하라.

### ☐ 2.3 시나리오 로직

기본 모델과 각 시나리오 간의 논리적 차이를 상세히 기술하라. 차이가 크면 2.2와
같은 방식으로 기술해도 된다.

### ☐ 2.4 알고리즘

현실의 복잡한·수작업 프로세스를 모사하는 알고리즘(도착·예약·작업 스케줄링,
설비 고장 등)을 재현 가능한 수준으로 상세히 기술하라(또는 기존 문헌을 인용하라).
의사코드를 써도 된다.

### 2.5 구성요소

#### ☐ 2.5.1 개체

시뮬레이션 내 모든 개체와 모델에서의 역할, 모든 속성을 기술하라.

#### ☐ 2.5.2 활동

개체가 모델 내에서 수행하는 활동을 기술하라. 활동 전후의 개체 라우팅을 상세히
제시하라.

#### ☐ 2.5.3 자원

모델 내 모든 자원과 이를 사용하는 활동을 나열하라.

#### ☐ 2.5.4 대기열

모델에서 가정한 대기열 규율(FIFO, LIFO, 우선순위 등)을 상세히 제시하라. 규율이
다른 대기열이 있으면 목록으로 제시하고 각각의 규율을 표시하라. 이탈(reneging)·
회피(balking)·이동(jockeying)이 있으면 규칙을 상세히 기술하라. 대기열의 지연이나
용량 제약도 기술하라.

#### ☐ 2.5.5 진입/이탈 지점

모델 경계, 즉 개체의 모든 도착·이탈 지점을 상세히 제시하라. 도착 메커니즘
(예: 비동질 포아송 과정을 모사하는 thinning, 회피 등)을 상세히 기술하라.

## 3. 데이터 (Data)

### 3.1 데이터 출처

모든 데이터 출처를 나열하고 상술하라. 출처에는 이해관계자 인터뷰, 일상 수집 데이터
표본, 연구 목적으로 수집한 표본, 학술·기관 문헌의 공개 데이터가 포함될 수 있다.
가능하면 링크와 DOI 또는 문헌 참조를 제공하라. **모든 출처 설명에 표본 크기,
표본 기간, 연구 내 용도를 포함하라.**

→ [docs/data_sources.md](data_sources.md) — 표1 데이터 파일(행수·표본 기간·용도·공개 여부), 표2 문헌·구술 근거, 비공개·부존재 사유

### 3.2 전처리

시뮬레이션에 쓰기 전 수행한 모든 데이터 가공을 상세히 기술하라
(예: 결측 보간, 이상치 제거).

→ [docs/preprocessing_log.md](preprocessing_log.md) — 코드 수행 9건(A-1~A-9), 소급 기록 7건(B-1~B-7), 알려진 이슈 7건(C-1~C-7)

### ☐ 3.3 입력 파라미터

모델의 모든 입력변수를 나열하고, 용도 설명과 파라미터 값을 포함하라. 확률적 입력은
사용한 연속·이산·경험적 분포와 관련 파라미터를 모두 제시하라. 시간의존 파라미터와
상관관계도 기술하라. 다음을 명확히 구분하라:

- 기본 케이스 데이터
- 기본과 다른 실험용 데이터
- 최적화·실험계획법 사용 시 파라미터가 취할 수 있는 값의 범위
- 이론적 분포를 쓴 경우 다른 후보 분포보다 우선 선정한 근거

### ☐ 3.4 가정

실제 시스템에 대한 데이터나 지식이 없는 부분에서 어떤 가정을 포함했는가?
파라미터 값, 분포, 모델 내 라우팅 로직 등이 해당될 수 있다.

## 4. 실험 (Experimentation)

### ☐ 4.1 초기화

모델링한 시스템이 종료형(terminating)인지 비종료형(non-terminating)인지 보고하라.
워밍업 기간을 사용했다면 길이와 그 선정에 쓴 분석 방법을 명시하라. 종료형이면
종료 조건을 명시하라. 사전 적재된 대기열·활동 등 초기 조건이 있으면 무엇인지
밝히고, 그 초기화가 결정적(deterministic)인지 확률적(stochastic)인지 보고하라.

### ☐ 4.2 실행 길이

시뮬레이션 모델의 실행 길이와 시간 단위를 상세히 기술하라.

### ☐ 4.3 추정 방법

확률성을 다루기 위해 사용한 방법을 명시하라(예: 다중 반복 실행 또는 배치 평균).
다중 반복이면 반복 횟수를, 배치 평균이면 배치 길이와 표준·간격·중첩 여부를
명시하라. 두 경우 모두 방법 선택과 반복 횟수·배치 크기에 대한 정당화를 제시하라.

## 5. 구현 (Implementation)

### 5.1 소프트웨어·프로그래밍 언어

운영체제와 버전·빌드번호를 명시하라. 모델을 구현한 상용·오픈소스 DES 소프트웨어의
이름·버전·빌드번호를 명시하라. 사용한 범용 프로그래밍 언어의 이름과 버전을
명시하라(예: Python 3.5). 프레임워크·라이브러리를 사용한 경우 버전 번호를 포함해
전부 제시하라.

→ [docs/tech_stack.md](tech_stack.md) — OS 빌드 10.0.26200 / Python 3.14.3 / SimPy 4.1.2 / 라이브러리 13개 설치 버전 / pandas 2.x 상한 근거

### ☐ 5.2 난수 샘플링

사용한 소프트웨어·언어에서 난수 표본을 생성하는 알고리즘을 명시하라
(예: Mersenne Twister). 공통난수(common random numbers)를 사용한다면 시드
(또는 난수 스트림)를 샘플링 프로세스들에 어떻게 배분하는지 명시하라.

→ [docs/tech_stack.md](tech_stack.md) 에 알고리즘(PCG64, Mersenne Twister 아님)은 확정.
**시드 배분·공통난수 사용 여부가 미정이라 미충족으로 둔다** — 배차 엔진 구현과 함께 결정.

### ☐ 5.3 모델 실행

이벤트 처리 메커니즘을 명시하라(예: three phase, event, activity,
process interaction). 개체·활동이 자원을 두고 경쟁하는 경우 모든 우선순위 규칙을
명시하라. 병렬·분산·그리드·클라우드를 사용하면 기술을 명시하고 가급적 인용하라.
병렬·분산 시뮬레이션이면 시간 관리 알고리즘도 명시하라. HLA를 사용하면 표준 버전,
런타임 인프라와 그 버전, 지원 문서를 명시하라.

### ☐ 5.4 시스템 사양

모델 실행 시간과 사용한 하드웨어 사양을 명시하라. 대규모 모델에서 특히 중요하다.
병렬·분산·클라우드를 사용하면 구현에 쓴 모든 시스템의 상세(프로세서, 네트워크 등)를
명시하라.

## 6. 코드 접근 (Code Access)

### ☐ 6.1 컴퓨터 모델 공유 진술

논문에 기술된 모델, 시뮬레이션 소프트웨어, 결과 재현에 필요한 기타 소프트웨어
(또는 하드웨어)를 다른 사람이 어떻게 입수할 수 있는지 기술하라. 가능하면 링크와
DOI를 제공하라.
