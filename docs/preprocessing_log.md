# 전처리 로그

**대응 STRESS 항목: 3.2 전처리**
(시뮬레이션에 쓰기 전 수행한 모든 데이터 가공을 상세히 기술하라 — 결측 보간, 이상치 제거 등)

시뮬레이션 입력을 만들기까지 원천 데이터에 가한 모든 가공을 **수행 시점 / 대상 데이터 /
가공 내용 / 제외·변경된 건수 / 근거** 로 기록한다.

기록은 두 갈래다.

- **A. 코드 수행** — `simulation/src/*` 와 `analysis/step7_idle.py` 에 있어 재실행하면
  같은 결과가 나온다. 건수는 전부 해당 모듈·함수를 실행해 얻은 값이며, 값마다 산출
  위치를 적었다.
- **B. 소급 기록** — 코드 밖(수작업·외부 도구)에서 수행됐다. **각 항목에 "소급 기록"임을
  명시했다.** 작업 당시 로그가 아니라 사후에 정리한 기록이라 건수·기준이 결과물과 작업자
  진술에 의존한다. 그중 B-3 은 A-9 로 재현되고 B-4 는 노트북 실물이 확인돼 근거가
  보강됐다.

산출물 기준 시점 — 콜 캐시 `2026-07-28 01:20`, 이동시간 캐시 `2026-08-03 22:51`,
동별 지표·차량 생산성·유휴 구간 `2026-08-05`.

### A-2. 동 좌표 매칭 3단계

| 항목 | 내용 |

**3단계와 건수**

| 단계 | 방식 | 색인 키 | 조회표 키 수 | 매칭된 출발 콜 |

| | | **계** | **674** | **1,527,213** |

`MANUAL_DONG` = {(종로구, 명륜3가동) → 혜화동, (동대문구, 용두동) → 용신동,

조회 순서는 **canon 먼저, 실패 시 base**. 어느 쪽에도 없으면 조회표에 넣지 않는다.

**목적동** 도 같은 절차를 거치지만 좌표가 없어도 행을 버리지 않는다.
`dest_match` 분포: exact 1,365,428 / approx 41,612 / manual 9,269 /
**좌표없음 110,904건(7.26%)**. 대부분 서울 밖 목적지다.

**근거** — 출발 좌표는 배차 계산에 필수라 매칭 실패 시 행을 버려야 하지만, 목적 좌표는

### A-6. 이용률 — 행정구역 판 불일치 처리

| 항목 | 내용 |
|---|---|
| 수행 시점 | 동별 표 산출 시마다 재수행. 현행 산출물 **2026-08-04 18:57** |
| 대상 데이터 | 콜 동 구분 **432개** × 등록 장애인 통계 동 구분 **427개** |
| 수행 위치 | `metrics.dong_population()`, `metrics.build_dong_table()` |

표준형(`canon_dong`)만으로는 432개 중 **18개**가 안 맞는다. 어긋나는 **방향에 따라 둘로
나눠** 처리한다. 둘 다 **나누는 게 아니라 합치는** 것이라 근거가 있다.

| 방향 | 예 | 처리 | 결과 컬럼 |
|---|---|---|---|
| 콜이 더 뭉뚱그림 | 강동구 상일동 ↔ 통계 상일1·2동 | 통계 쪽을 기본명 그룹으로 합산해 그 동에 붙인다 | `pop_match='base'` |
| 콜이 더 잘게 쪼갬 | 중구 신당1~6동 ↔ 통계 신당동 | **콜도** 같은 기본명 그룹으로 합산해 분자·분모의 단위를 맞춘다 | `usage_is_grouped=True` |

**세부 규칙**

- 기본명 그룹을 **두 개 이상의 동이 다투면 `n_disabled` 를 붙이지 않는다** — 통계 한 줄을
  어떻게 나눌지 근거가 없어서다.
- 이미 표준형으로 붙은 통계 행은 기본명 후보에서 뺀다(공릉2동 이중 계상 방지).
- `min_count=1` — 통계값이 `-`(NaN)뿐인 그룹까지 0명으로 만들지 않는다.
- `pop_group` 은 잔여분이 아니라 **그룹 전체** 인구다. 답십리3·4동을 살리려면 이미 정확히
  붙은 답십리1·2동의 인구까지 분모에 들어가야 하고, 그러려면 콜도 4개 동을 다 더해야 한다.

**적용 건수** (`outputs/dong_metrics.csv` 실측)

| 구분 | 값 |
|---|---|
| 양방향 그룹 합산 적용 동 | **24개 동 / 7개 기본명 그룹** |
| 그룹 목록 | 신당1~6동, 답십리1~4동, 장안1~4동, 이문1~3동, 전농1~3동, 제기1·2동, 일원1·2동 |
| `pop_match` 분포 | canon 414 / base 2 / 미매칭 16 |
| 이용률 산출 불가(NaN) | **2개 동** — 반포본동, 명륜3가동 |
| `n_disabled` 합 | 378,097명 (통계 총합 384,921명 이하) |

### A-8. 캐시 무효화 방식

| 항목 | 내용 |
|---|---|
| 수행 위치 | `load._cache_path()`, `travel_time._cache_paths()` |
| 저장 위치 | `simulation/cache/` (산출물이라 읽기전용일 수 있는 데이터 폴더가 아니라 저장소 안에 둔다) |

| 캐시 | 파일명 규칙 | 무효화 트리거 |
|---|---|---|
| 콜 | `calls_{o\|od}_{mtime}_{size}.parquet` | 원본 CSV 의 mtime 또는 크기 변경. `od` 태그는 `require_seoul_dest=True` 로 만든 캐시라 두 설정이 서로 덮어쓰지 않는다 |
| 이동시간 | `travel_{od\|speed\|profile}_{mtime}_{size}_{crc32}.parquet` | 원본 변경 **또는** 산출 상수 변경 |

이동시간 캐시의 `crc32` 는
`(MIN_TRIPS, MIN_SPEED_TRIPS, PERIOD_CUTS, DIST_CUTS, RIDE_MIN_RANGE, SPEED_RANGE)`
의 해시다. **상수만 바꿔도 캐시가 저절로 빗나가 다시 만든다** — 상수를 고치고 옛 테이블을
계속 쓰는 사고를 막는 장치다.

무효화는 **파일명이 달라지는 방식**이라 옛 캐시를 지우지 않는다. 원본이 바뀌면 새 이름으로
새 파일이 생기고 옛 파일은 그대로 남는다(수동 정리 필요).

현행 캐시 파일 — `calls_o_1784023283_338587487.parquet`,
`travel_{od,speed,profile}_1785738239_371403001_3d09c96a.parquet`.

## C. 알려진 이슈

전처리 결과에 남아 있는 미해결 문제다. 값을 인용할 때 함께 읽어야 한다.

### C-1. 공영주차장 좌표 유효 1,456 / 2,189

`공영주차장_목록.csv` 2,189곳 중 좌표가 유효한 건 **1,456곳(전부 시영)** 이고,
나머지 **733곳(전부 자치구영)** 은 `LAT`/`LOT` 가 모두 0 이다. 즉 좌표 필터를 걸면
**후보지 풀이 시영 전용**이 된다. 구영을 후보에 넣으려면 주소 지오코딩이 선행돼야 한다.

`시영주차장_목록.csv` 122행 중 **117행**만 공영 파일에 `PKLT_CD` 로 존재한다(5행은 없음).

### C-2. 차고지 44곳 중 12곳이 도로명주소

`차고지44_좌표.csv` 의 `상세주소` 중 도로명 체계로 적힌 것이 **12곳**이고 나머지는 지번
표기다. 표기 체계가 섞여 있어 주소 문자열 조인·재지오코딩 시 규칙을 하나로 잡을 수 없다.

좌표는 44곳 전부 확보돼 있고 구 불일치 경고는 0건이라 **현재 지표 계산에는 영향이 없다.**
문제가 되는 건 주소를 키로 다른 대장(주차장 목록 등)과 맞출 때다.

### C-3. 동명 조인 시 신사동(강남·관악) 충돌

`travel_time.get_travel_time(출발동, 목적동, hour, is_weekend)` 시그니처가 **구를 받지
않아 동명만으로 조회**한다. 그래서 구가 다른 동명이 겹치면 구분할 수 없다.

| 항목 | 내용 |
|---|---|
| 처리 | `travel_time.load_centroids()` 가 겹치는 동명의 **중심점을 평균**한다 |
| 규모 | canon 키 **425개 중 1개**(`attrs['n_ambiguous']`) — 신사동(강남구·관악구) |
| 영향 | 1순위 실측 OD 셀에서도 두 동의 운행이 한 셀에 섞인다. 2·3순위 근사에서는 평균 좌표로 거리를 재므로 오차로 남는다 |

`load.build_dong_lookup()` 은 (구, 동) 두 키를 쓰므로 이 문제가 없다 — **충돌은
`travel_time` 쪽에만 있다.**

### C-4. 목적동 좌표 결측 110,904건(7.26%)

대부분 서울 밖 목적지다. 서울 내 미매칭은 극소수이며 전부 **인천 중구 동(영종동·율목동·
북성동·신흥동·도원동·연안동)이 서울 중구로 잘못 적재된 건**이다. 이동시간 조회에서
좌표없음 폴백(`default`)으로 처리되며 323건 · 전체의 0.02% · 절대중앙오차 57.3분이다.

### C-5. `load_disabled_population()` 은 원본 행 순서에 의존한다

구 컬럼이 따로 없어, 구 행이 그 구의 동들 앞에 오는 순서에 기대어 `ffill` 로 구를 채운다.
**원본 통계표의 정렬이 바뀌면 구가 잘못 채워진다.**

### C-6. 행정구역 판이 세 갈래다

콜 432개 동 / 경계 파일 426개 / 통계 427개. 어느 쪽도 완전히 겹치지 않아 조인마다 별도
규칙이 필요하다(A-2, A-6). 이 불일치는 데이터 소스가 서로 다른 시점의 행정구역 개편을
반영해서 생긴 것이라 전처리로 완전히 없앨 수 없다.

### C-7. 유휴 구간의 위치를 알 수 없다

A-9 가 내는 것은 구간의 **길이**뿐이다. 차량이 그 시간 동안 **어디에** 서 있었는지는
원본에 없다. 하차지 인근에 머물렀다는 가정(A-01)은 실측으로 확인되지 않았고, 거점
배치 효과를 실측만으로 검증할 수 없는 이유이기도 하다 — 시뮬이 필요한 지점이다.
